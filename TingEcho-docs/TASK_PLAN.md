# TingEcho 开发计划

依据 [PRD](PRD.md) 和 [架构方案](ARCHITECTURE.md)。以下为建议执行顺序，实际结果追加到 [PROGRESS.md](PROGRESS.md)。

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1. 建立基线 | 核对三端工具链及现有构建流程。准备脱敏旧 ZIP/JSON 和一组含图、音、视频、隐藏记录及位置天气的样本。安卓验证现场原声录制。 | 记录实际构建与设备环境，标明基线失败和录音缺口。提前确认 iOS 构建所需的 macOS/Xcode 环境。 |
| 2. 更名与安装隔离 | 盘点旧品牌和安装标识，更新 Dart 包、三端配置、后台任务、服务发现和发布脚本。对备份与同步涉及的标识先用样本验证再改。 | 两款应用可在同设备共存，数据与凭据独立。TingEcho 设备互相发现并同步，既有备份可导入。完成旧命名扫描和产物检查。 |
| 3. 随手记与成长主题 | 改首页入口和主题列表；从主题打开原编辑器并预选标签；支持保存后补选及标签改名。有录音缺口时接入现有附件链路。 | 安卓断网可首次保存，重启可见，主题内接着记无需重选。图片、原声和视频能独立成条，权限拒绝或保存重试可恢复。 |
| 4. 看看变化 | 展示首末记录，支持重选、回原文、播放及写感想。覆盖零、一、多条及窄屏、宽窗。统一处理隐藏、删除、恢复后的刷新。 | 对照使用原记录与播放器，媒体切换不会同时播放，隐藏内容及数量不会泄露。 |
| 5. 首版验收 | 按 PRD 的 DoD 跑三端构建、安装、启动和核心流程；验证语言、亮暗、大字号、离线、权限及备份同步。邀请首位用户完成核心操作。 | 安卓 ZIP 在 Windows 恢复并打开三类媒体；旧格式导入、重复导入、局域网及 WebDAV 同步有记录。三端及语言机制通过，用户可独立完成记录、接着记和回看。 |

阶段 1 可为 2 和 3 提供基线，阶段 4 依赖主题入口与现有媒体能力，阶段 5 汇总所有 P0 验收。每阶段先跑现有相关测试和静态检查，根据实际回归补针对性用例。验证记录包含提交、命令或手工步骤、设备系统、通过项及失败项；缺少对应设备的项目标为待验收。首版交付后按使用反馈确定 P1 的轻复盘、来信和助手顺序。
