# TingEcho 架构方案

基于 [PRD](PRD.md) 与 TingEcho 分支的 ThoughtEcho 基线 3beee52。首版采用现有 Flutter 应用内的增量改造，继续支持 Android、Windows、iOS 和现有八份语言资源。

## 界面与调用边界

| 功能 | 设计 |
| --- | --- |
| 首页 | 在现有导航和首页入口调整信息顺序，显示记一下、最近主题、最近记录。沿用 home_note_editor_actions.dart 与 NoteListView，保留搜索和进入设置的路径。 |
| 成长主题 | 主题对应现有普通用户标签。以 NoteTag.id 路由，复用标签管理与 DatabaseService 的标签过滤和分页。最近主题按其最新可见记录时间排序，暂无记录的主题仍可从主题列表打开。 |
| 随手记 | 从主题打开编辑器时传入预选标签 ID，从首页打开时可留空。编辑已有记录时加载其现有标签。标签变更随笔记一起保存，沿用草稿、媒体转存、失败处理及刷新。 |
| 看看变化 | 以主题 ID 查询最早和最近的可见笔记，时间相同以笔记 ID 稳定排序。使用既有富文本渲染和播放器封装；切换播放或离开页面时暂停。选择器分页读取记录，点击回原文；感想走同一新增入口。 |
| 原有功能 | 地图、备份、局域网/WebDAV、模型配置、助手和推送继续使用现有页面与服务。次要入口收进更多或设置。亮暗主题、字号和翻译沿用现有机制。 |

界面依赖现有 Provider 和服务。只有当现有查询无法高效取出主题首末记录或最近主题时，才在现有数据库查询层补充窄接口，并沿用当前索引和查询约束。所有新增界面由同一可见记录集合生成正文、媒体、计数和候选项；隐藏、删除、换标签和恢复后刷新，打开详情时重新校验可见性。

## 数据、媒体和兼容性

- 首版继续使用 Quote、NoteTag、tagIds、正文和 Quill Delta。主题改名保留 ID。同一条笔记可挂多个主题，复盘对照读取原记录。首版主题和对照设计无需新增数据表。
- 复用 unified_media_import_dialog.dart、MediaFileService 和现有播放器。先在安卓查证原声直录。如果缺口成立，仅补采集和试听，把结果送进现有音频附件入口，覆盖取消、拒绝权限、临时文件清理和保存重试。
- 地点和天气沿用记录快照及原权限入口。离线或服务失败仍可保存。ZIP 沿用 BackupService 的带媒体导出、路径修复和恢复。旧 ZIP/JSON 用脱敏样本验证。局域网和 WebDAV 沿用现有同步流程。
- 新应用独立安装、独立数据和凭据。全局更名涉及 Dart 包和导入、三端应用标识、平台通道、后台任务、服务发现、同步标识及打包配置。逐项区分显示名称、安装身份与持久格式。旧备份若需要识别历史标记，在导入边界集中兼容，并用原版备份样本验证。品牌扫描发现无法兼容的历史标记时记录具体位置与方案再定稿。
- 现有本地化生成流程和语言切换继续使用。新增界面沿用仓库翻译回退约定，沿用主题令牌。手机纵向对照，桌面宽窗并排，窄窗回到纵向。

## 后续扩展

周期复盘引用可见笔记 ID；来信复用已有推送与内容选择，锁屏使用通用文案；助手复用模型配置和提案确认。三项按 PRD 后续优先级推进。外部模型只接收用户选定授权范围内的记录。
